# 5. Refactorización

Revisión inicial: `v1-inicial` (`844c0ff`). Revisión final: `v2-final` (`6c3de74`).

Todos los cambios están en `app/orders.py`. Las 61 pruebas iniciales siguen pasando (solo cambió la llamada `save(...)` por `create(data)` en una prueba unitaria) y se agregaron 5 pruebas para `calculate_totals`. El esquema OpenAPI es idéntico al de `v1-inicial`.

## 1. Extract Function

**Problema:** cálculo de descuento y envío duplicado en `save` y `quote` (smell 1).

Antes, en `save` y en `quote`:
```python
if customer["category"] == "premium":
    discount = subtotal * 10 // 100
elif customer["category"] == "business":
    discount = subtotal * 15 // 100
else:
    discount = 0
...
total = subtotal - discount + delivery
```

Después:
```python
def calculate_totals(subtotal, category, shipping):
    discount = subtotal * DISCOUNT_PERCENT.get(category, 0) // 100
    delivery = SHIPPING_CENTS[shipping]
    if shipping == "standard" and subtotal >= FREE_STANDARD_SHIPPING_FROM:
        delivery = 0
    return {"subtotal_cents": subtotal, "discount_cents": discount,
            "shipping_cents": delivery, "total_cents": subtotal - discount + delivery}
```

Las reglas están en un solo lugar, la cotización y el pedido guardado no pueden diferir, y el cálculo se prueba sin base de datos.

## 2. Introduce Parameter Object

**Problema:** `save` recibía seis valores sueltos sacados de `OrderInput` (smell 3).

Antes:
```python
def save(self, customer_id, address, city, postal_code, shipping, items, order_id=None):

OrderService(request.app.state.database).save(
    data.customer_id, data.address, data.city, data.postal_code, data.shipping, data.items,
)
```

Después:
```python
def create(self, data):

OrderService(request.app.state.database).create(data)
```

Agregar un campo al pedido ya no obliga a cambiar la firma ni las llamadas, y no hay riesgo de confundir el orden de los argumentos.

## 3. Remove Flag Argument

**Problema:** `order_id=None` decidía si `save` creaba o actualizaba, lo que hacía largo el método y mezclaba dos flujos (smells 2 y 3).

Antes:
```python
def save(self, ..., order_id=None):
    if order_id is not None:
        # validar pedido existente y pendiente
    ...
    if order_id is None:
        # INSERT
    else:
        # UPDATE + DELETE items
```

Después:
```python
def create(self, data):
    customer, lines, totals = self._price(connection, data)
    ...

def update(self, order_id, data):
    self._pending_order(connection, order_id, "Solo puede editar pedidos pendientes")
    customer, lines, totals = self._price(connection, data)
    ...
```

Cada método hace una sola cosa. La parte común se extrajo a `_price`, `_insert_items` y `_load`, y la búsqueda "pedido o 404" que se repetía en cinco métodos quedó en `_find_order` / `_pending_order`.

## 4. Replace Magic Literal

**Problema:** estados, categorías y envíos como cadenas y números repartidos por el código (smell 4).

Antes:
```python
if order["status"] != "pending":
connection.execute("UPDATE orders SET status = 'confirmed' WHERE id = ?", (order_id,))
delivery = 0 if subtotal >= 10_000 else 1_000
```

Después:
```python
class OrderStatus(StrEnum):
    PENDING = "pending"
    CONFIRMED = "confirmed"
    CANCELLED = "cancelled"

DISCOUNT_PERCENT = {"premium": 10, "business": 15}
SHIPPING_CENTS = {"pickup": 0, "standard": 1_000, "express": 2_500}
FREE_STANDARD_SHIPPING_FROM = 10_000

if order["status"] != OrderStatus.PENDING:
self._set_status(connection, order_id, OrderStatus.CONFIRMED)
```

Los valores válidos están definidos una vez y un error de escritura (`OrderStatus.PENDNG`) falla de inmediato en vez de pasar en silencio.
